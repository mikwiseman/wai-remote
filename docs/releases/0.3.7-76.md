# WAI Remote 0.3.7 — Mac 76 candidate, iPhone 73 delivered

Full-desktop clicks bring the selected window and its app forward while keeping the remote pointer separate. The clicked frame is captured before activation; no click is redirected after a window moves. Hover, scrolling and held drags do not activate another app. Existing single-window grants keep background input.

Save-panel keyboard routing identifies the owner of the exact remote window linked to the selected sheet. This covers compact panels on macOS 26, whose accessibility proxies hide the service PID. The outer sheet still supplies scope and geometry. Compact Cancel, Unicode, physical keys and Escape pass on macOS 26 and 27. Expanded filename editing and Cancel pass in the native fixture. An unconditional first-Escape-after-expansion assertion was replaced with focused-field interaction: the correctly keyed native AppKit reference also consumed that first Escape. No cancellation override was added.

Menu items use their native Press action. AppKit can keep a document's accessibility window ID after creating a separate WindowServer menu; the correction validates the current hit, exact menu geometry, owner and pointer-overlay exclusions. Disabled items retain document provenance without performing an action. Menu clicks preserve typing only for the same previously selected document, and do not reactivate a tracking menu. The own-app activation callback also retains its escaping cancellation predicate safely.

The new popup regression first reproduced failed selection and lost typing. The corrected fixture passes with WAI's actual cursor overlay, normal and Shift-disabled taps, overlapping-window rejection, canceled input, one selection, continued typing and a stationary physical pointer. All 19 menu, modal and desktop-routing cases pass locally. Three foreign-window activation cases encountered a local helper-already-frontmost setup failure; their assertions remain intact and isolated CI is the final gate. Temporary diagnostic tracing was removed.

iPhone 73 defers keyboard-dismissal state changes until focus settles and ignores a stale dismissal after reopening. Two native regressions failed before correction; seven keyboard tests and the actual keyboard UI passed afterward without the SwiftUI state-update warning. The final [iOS CI job](https://github.com/mikwiseman/wai-remote/actions/runs/41314088725/job/124870356973) passed all 45 tests with no skips or failures on `be0521c83c8f26f1cb4f57344dc1b585b30b55c1`. Its signed archive/export passed version, signature, existing-profile and DEBUG-recorder-exclusion checks.

Four native SessionView tests pass: zoom/pan/Fit and off-center taps, hold-drag/release, software typing, keyboard controls and overlay dismissal. They use rendered screenshot targets and public XCUITest gestures. They do not prove physical iPhone scrolling, network handover or all-network latency. The default CI unit scheme is unchanged; the dedicated `WAIRemotePhoneInteraction` scheme provides the full-screen tests.
