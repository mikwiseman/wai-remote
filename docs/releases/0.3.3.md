# WAI Remote 0.3.3

macOS build 61 · iOS build 62 · 18 October 2026

## Changes

- Preserve the owner's open-access grant and background recovery after a rejected signaling connection. Retry with a fresh signed challenge. Explicit Close Access still revokes the grant.
- Distinguish handshake transport failures from invalid device signatures at the gateway. Show actual server registration and recovery in the Mac interface.
- Offer one hour, 24 hours, or until revoked when approving a new device. Check expiry during connection and active use. Existing approvals without an expiry remain indefinite.
- Connect through a QR code on Mac, iPhone/iPad and the web. Camera frames and selected QR images stay on the receiving device. Handle iOS Simulator's Vision decoding failure separately from the physical-device camera path.
- Keep recent content-free diagnostics in two bounded log files, so a long-running host retains recovery evidence.
- Use the current UDP relay configuration with TCP fallback on iOS, matching the Mac viewer, and prefer H.264 while retaining other supported codecs.

The independent mouse, native Liquid Glass interface, saved computers and background recovery from earlier releases remain available. Independent input addresses application windows; it is not a second macOS login session. Applications and the clipboard are shared.

## Validation and distribution

- 135 Swift tests: zero failures, one opt-in integration test skipped. Both hosted iOS QR tests pass after reproducing the original Simulator failures. Go race tests and the web production build pass.
- The universal Mac app and DMG passed Developer ID verification, Apple notarization, stapling and Gatekeeper checks. The app inside the mounted DMG was checked independently.
- Mini completed the real Sparkle 59→61 installation and relaunch. Its owner grant, original trusted peers, keychain identity metadata and TCC permissions were preserved. The temporary preview feed override was removed.
- Terminating only the installed host process caused the existing recovery helper to relaunch build 61 in 28.76 seconds without a manual launch. The owner grant survived and the interface returned to access open.
- The gateway was deployed with a timestamped backup and atomic replacement. Local health and fresh signed authentication through the public hostname passed. Public web assets match the built files.
- Apple processed iOS 62 as VALID and made it IN_BETA_TESTING for the existing WAI Remote Internal group. Its transport and codec preferences now match the Mac viewer. The third-party WebRTC dSYM warning remains; application symbols are preserved.
- All three CI jobs pass on main. The video recovery test now feeds a continuing frame stream, allowing the native display to drop an individual frame under backpressure as it does in normal playback.

The iOS 61 synthetic test carried live video and input for more than eleven minutes before a simultaneous host/viewer network failure. Both clients observed connection refusal on the current VPN path while the gateway and HTTPS edge remained running, then reconnected without new approval. The complete 12-minute uninterrupted gate did not pass; this result is not described as a continuous-session pass.

The iOS 62 follow-up also reconnected during the sustained check. The check stopped after 284 seconds because uninterrupted operation had already failed. Public HTTPS health requests timed out near the failure while the gateway and TURN processes remained active without restarts. Video resumed without new approval and a subsequent click advanced the test counter. These observations confirm recovery, not uninterrupted availability; the underlying network cause remains unconfirmed. The Simulator negotiated VP8, so H.264 operation still needs a physical-device check.

The physical iPhone and second Mac were unavailable for this release check. Physical camera, two-network operation, lock/unlock and cold login are not newly verified by this release. Synthetic Simulator checks do not establish desktop video smoothness or input-to-display latency.
