# WAI Remote 0.3.7 (72) — candidate

Two-finger scrolling on iPhone could miss a gesture, mistake staggered fingers for a pinch, or jump when recognition began. The viewer now keeps a stable touch pair, reads UIKit's complete touch snapshot, accepts a finger starting in the letterbox when the pair targets the screen, consumes recognition slop, and delivers movement at lift. A third finger cannot change the scroll target. Tap, pinch and one-finger viewport navigation retain their existing meanings.

Scroll movement is accumulated once per display frame. Momentum uses elapsed time and UIKit's normal deceleration rate. Congestion retains pending drag distance without generating an input backlog; interrupted or stale momentum stops. Focus, mode, surface, epoch and Fit Screen changes cancel the gesture. The Mac receives precise pixel events with native scroll/momentum phases and keeps the original window for the gesture. Compatible pending movement is combined without crossing keys, phase boundaries, direction changes or session changes.

The implementation follows [UIKit's changed-touch contract](https://developer.apple.com/documentation/uikit/uiresponder/touchesmoved(_:with:)), [UIScrollView deceleration](https://developer.apple.com/documentation/uikit/uiscrollview/decelerationrate-swift.property), and [AppKit's scroll and momentum lifecycle](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/HandlingTouchEvents/HandlingTouchEvents.html). Optional wire fields preserve legacy clients; existing permission and session validation remains in force.

Host signaling callbacks also use the main run loop's common modes. A bounded real WebSocket regression reproduced false timeouts and blocked re-registration during menu tracking; all eight signaling tests pass after the two scheduling changes. Socket identity and cancellation checks remain unchanged. This defect is confirmed, but its role in the live Mini outage is not: both clients currently report the host unavailable while the public gateway and relay remain healthy.

## Verification in progress

- Six native iOS regressions failed against the previous implementation, then passed with the correction. Twelve gesture tests, seven stream tests and seven existing screen tests pass, covering pinch limits, cancellation, 60/120 Hz distance, momentum, congestion, stale callbacks and Fit Screen.
- The host regressions failed before correction. The final focused Mac suite passed 40 tests, including native CGEvent-to-NSEvent phase/precision readback, target retention and queued movement.
- Three protocol regressions and the related session/viewer suite passed: 24 tests.
- A real iOS WebRTC test delivered and echoed all 374 ordered scroll/key packets with exact distance totals, cancellation and barriers. Decoded H.264 pixels contain frame IDs linked to received input. This is a same-process simulator benchmark, not physical iPhone-to-Mac latency. Its initial video delay is under investigation. Later local runs fail at ICE setup with zero candidate pairs; stage diagnostics now distinguish connection setup from input/video timing. No production transport tuning is justified by those failed runs.
