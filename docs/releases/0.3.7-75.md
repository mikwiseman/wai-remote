# WAI Remote 0.3.7 — Mac 75 candidate, iPhone 72

Completes remote input support for macOS Save panels hosted in a separate process. Build 74 live Mini testing exposed the additional accessibility layer that ordinary modal-sheet tests did not cover.

The host now follows the selected sheet's accessibility bridge to its remote keyboard receiver while retaining the outer window for validation and pointer geometry. Button lookup stays within the hit sheet. Escape includes the character needed by background native key equivalents. Input does not activate another app or fall back to global injection.

29 native tests pass without skips, including a real NSSavePanel: Cancel, Escape, Unicode text, a physical key, and rejection after the outer sheet closes. This extends the existing modal and selected-window routing coverage.

Build 75 is a preview only; the normal feed remains 74. The universal app and DMG passed notarization, stapling, Gatekeeper, mounted-app verification and public Sparkle byte/signature checks. MacBook updated 74→75 through Sparkle with saved computers and access unchanged; the temporary preview-feed override was removed.

Wider rollout is paused. [CI](https://github.com/mikwiseman/wai-remote/actions/runs/41311211528) passed the iOS, gateway and browser checks but exposed Save-panel keyboard failures on macOS 26.6.2, despite the local macOS 27.0.1 native pass. A diagnostic rerun showed a compact-panel accessibility tree without the foreign-process descendant used by the receiver lookup; extending the lookup budget did not help. The independent late-callback failure in the WebSocket test fixture was reproduced and corrected without changing production signaling.

Live Mini verification of Delete and ordinary window controls is still required. Physical iPhone scrolling acceptance remains pending: the user could not test scrolling while window interaction was failing. This preview is not a completed fix for that report.
