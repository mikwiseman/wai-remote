# WAI Remote 0.3.7 — Mac 71, iPhone 70

1 November 2026. Mac 71 fixes an additional input delay found after the occupied-connection update in [build 70](0.3.7-70.md). An accessibility action targeting WAI Remote itself could wait until its menu closed. All four same-process main-thread hops now schedule through common run-loop modes, which can execute inside a nested tracking loop. The serial input worker still waits for completion, and cancellation is checked before an action runs.

The regression failed before the fix, then passed. A second test cancels a queued old-session press, verifies that it never runs, and delivers a new-session press during tracking. All 33 focused input tests passed; independent code review approved the change. [Apple documents the run-loop scheduling API](https://developer.apple.com/documentation/foundation/runloop/perform(inmodes:block:)).

Source: `2224cd73bf171271fcd1495c22e90ffddbb19938`, [PR #9](https://github.com/mikwiseman/wai-remote/pull/9).

The [full source CI](https://github.com/mikwiseman/wai-remote/actions/runs/41292622513) passed 198 Swift tests (three explicit skips), 23 native iOS tests, gateway race tests and the browser build. The PR merged as `ed10e1aebea8c64e444c6224615af983eafa0dc9`; its source, tests and build configuration match the tested revision. A duplicate push workflow was cancelled. The identical merge tree did not repeat the same matrix.

This fix does not establish the cause of every missed menu selection on waiMini. Its installed version and actual input target were unavailable. Physical iPhone-to-Mini handoff and input-to-visible-text latency remain unverified. The QA viewer was explicitly disconnected. iPhone 70 remains available in the unchanged internal TestFlight group.
