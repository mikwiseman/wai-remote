# WAI Remote 0.3.7 — Mac 78

Desktop clicks activate the selected application even when WAI Remote runs in the background. The owner’s physical pointer stays separate, and single-window grants retain background input. This fixes the case where a window rose but another application kept keyboard focus.

Buttons inside a hosted macOS remote view are resolved through their exact link to the selected outer window. The app-scoped hit test can stop at that outer window or group; the correction follows only one containing remote child with a verified WindowServer owner and parent. Ambiguous branches, unrelated sheets and a changed window are rejected. This covers the real System Settings About button and standalone save-panel Cancel.

The activation and hosted-button regressions passed on macOS 26 and 27. Test helpers now wait for actual launch/deactivation acknowledgments and discover XPC controls from the calling process, leaving the target’s UI loop free. One-click actions, foreground identity, window scope and pointer assertions remain. A same-target scoped-input-to-desktop-click regression also passes.

Hosted popup menus, their selection and Escape routing are a separate open issue and are not claimed fixed in this build. iPhone 0.3.7 (73) remains available in TestFlight; its source is unchanged. Physical iPhone scrolling and end-to-end latency still require device acceptance.

Release gates: exact-source full CI, signed/notarized universal app and DMG, public signatures/bytes, preserved saved access through Sparkle installation, and actual Mini input/reconnection. Runtime evidence is recorded under `.runtime/agent78/` and `.release/publish-0.3.7-78/`.
