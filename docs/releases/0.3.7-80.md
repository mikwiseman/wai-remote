# WAI Remote 0.3.7 — Mac 80

Mac 80 fixes a crash when remote clicks activate WAI's own windows. AppKit window numbers outside the WindowServer ID range are compared without a trapping unsigned conversion. Both conversion traps were reproduced in the original code; two focused regressions now cover deferred, negative, oversized and exact matching values. Builds 76 and 79 contained this bug.

Background app activation, scoped hosted-control routing, popup selection, continued typing and bounded keyboard discovery remain included. The remote pointer stays separate, and single-window grants retain background input.

Source `df4285ac98f65691d193e59b1832c3f1b232a13f` passed [CI](https://github.com/mikwiseman/wai-remote/actions/runs/41338380037): 262 Swift tests with three existing skips and zero failures, 45 iOS tests, gateway race tests and the web build. The signed, notarized universal app and DMG are published through the normal Sparkle feed; public bytes and signatures matched.

The MacBook completed 79→80 through Sparkle. The Mini completed 76→80 through verified bundle replacement with its old bundle preserved: build 76 also crashed on Sparkle's Install button. Saved computers and access remained unchanged. The Mini installation is not recorded as Sparkle acceptance.

Live MacBook→Mini control through the installed agent CLI and WAI WebRTC passed:

- Native buttons, Unicode and 60 numbered text lines; controlled scrolling up, down and back to the document header.
- WAI Settings Check Updates and dismissal, formerly crashing; System Settings background activation and About navigation.
- AirDrop and iPhone-selector menus opened and closed with Escape without changing selections.
- SavePanel format menu, Escape and continued Unicode filename typing; Cancel and Delete each worked on the first click from the background.
- Saved-computer reconnection, stale-snapshot rejection and control using a fresh screenshot.

System Settings navigation followed a separate activation click; the AirDrop menu opened from its chevron. The physical pointer visually stayed in place, without new quantitative sampling. Test windows were cleaned up and the viewer disconnected. Evidence is recorded in `.runtime/agent80/live-acceptance.json` and `.release/publish-0.3.7-80/`; private screenshots are not published.

iPhone 0.3.7 (73) remains the delivered TestFlight build. Physical iPhone scrolling feel, end-to-end latency and LTE/Wi-Fi handover remain unverified; these checks do not establish behavior in every app or network.
